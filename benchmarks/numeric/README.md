# numbench - Cairo fixed-point benchmark for rapier-cairo

Empirical cost comparison (steps / builtins / l2_gas) of Cairo numeric libraries and of hand-written
signed fixed-point representations. Full write-up: [`docs/research/04-numeric-benchmark.md`](../../docs/research/04-numeric-benchmark.md).

Standalone workspace, deliberately outside the library workspace so third-party reference code
(cubit, Orion, alexandria — MIT, see the `LICENSE` file in each package) never leaks into it.

## Layout

```
.tool-versions                 scarb 2.19.4, starknet-foundry 0.61.0 (asdf)
Scarb.toml                     workspace; incremental compilation disabled (compiler panic otherwise)
packages/cubit                 copy of influenceth/cubit (src only, upstream unit tests stripped, 2 patches)
packages/orion                 copy of gizatechxyz/orion src (numbers + operators::{tensor,matrix,vec}; nn/ml/sequence dropped)
packages/alexandria_*          the 3 alexandria crates Orion needs (rev 800f5ad), trimmed
packages/bench                 the benchmark package `numbench`
  src/bb.cairo                 black_box / sink helpers (anti constant-folding)
  src/reprs/*.cairo            B: sm64, i64n (naive i64), i64b (i64 + BoundedInt), felt (lazy), sm128
  src/vecs.cairo               generic Vec2/Vec3/Mat3 kernels + fused kernels
  src/micro.cairo              mul-then-shift, DivRem variants, math vs bitwise vs loop
  src/sqrts.cairo              C: sqrt / inverse sqrt variants
  src/trig.cairo               D: polynomial sin/cos/atan2, Bhaskara
  tests/a_*.cairo              A (generated by scripts/gen_a.py)
  tests/b_*.cairo              B (generated by scripts/gen_b.py) + b_mulshift.cairo
  tests/c_sqrt, d_trig, d_sweep, e_orion_linalg, f_heuristic, g_pitfalls
scripts/run.py                 runs snforge twice, subtracts baselines -> results.json / results.md
scripts/sweep.py               trig accuracy from the SWEEP lines printed by d_sweep
```

All patches applied to third-party code are marked `NUMBENCH PATCH` (grep for it).

## Rerun

```sh
cd benchmarks/numeric
python3 scripts/gen_a.py && python3 scripts/gen_b.py   # only if you changed the generators
snforge test -p numbench                               # everything green (sierra-gas l2_gas)
python3 scripts/run.py                                 # both resource modes -> results.md / results.json
python3 scripts/sweep.py                               # trig error table -> sweep.json
```

`run.py` runs `snforge test -p numbench --detailed-resources --tracked-resource cairo-steps`
(steps + builtins) and `... --tracked-resource sierra-gas` (l2_gas; in cairo-steps mode l2_gas is
clamped to a 40000 floor so it is useless for micro-benchmarks).

Naming convention inside a test module: `base_<k>` is a baseline (same black-boxed inputs, same
sink, no operation), `<k>_<op>` is a benchmark that is reported net of `base_<k>`;
`check_*` / `sweep_*` tests are correctness / accuracy tests and are not reported.

Always pass `-p numbench`: a bare `snforge test` also tries to build test targets for the vendored
packages.
