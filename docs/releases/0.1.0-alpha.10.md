# Release record: 0.1.0-alpha.10

Record of what was published on scarbs.xyz as `0.1.0-alpha.10`, and how.

## The release commit

- Release commit: `f7a91363838a99e987dffb0c77fdd168114d6911`, on the branch `release/0.1.0-alpha.10` (kept, never
  merged), cut from `4d8e14a9a287eea3b18344b9c60f27d0f31cb735`, the merge of the release pull request #272.
- Its whole diff removes the `[dev-dependencies]` of the six published crates. Their test helpers, `rapier_testing` and
  `rapier_golden`, are not published, so the manifests on `main` could not be packaged. `main` keeps the
  dev-dependencies (`slingfall/OPERATIONS.md` §7, the project manager's ruling with the Overseer of 2026-10-03).
- The release commit was landed by fast-forward (#273, review PASS, Opus), never squash-merged, so the commit that was
  packaged is the commit on the branch.
- CI: every job that does not need the removed dev-dependencies is green on `f7a9136`; the test jobs and both sinks are
  green on `4d8e14a` on `main` (run 37171579462).

## How it was published

- Five staged goes of the project manager, as for alpha.9, with the same commands: each crate verifies against its
  predecessors on the registry only after they are published, so a crate was packaged and published once the previous
  one was on the registry.
- Each archive was built by `RAYON_NUM_THREADS=1 scarb package -p <crate>` (no `--no-verify`, no `--allow-dirty`) from
  a clean clone detached at `f7a9136` (its `VCS.json` names that commit), compared with `sha256sum -c`, published with
  `scarb publish -p <crate>` by the orchestrator, and read back from the registry after each.
- Tag `v0.1.0-alpha.10` on `f7a9136` (annotated), and the GitHub release (pre-release):
  `https://github.com/bal7hazar/rapier-cairo/releases/tag/v0.1.0-alpha.10`.
