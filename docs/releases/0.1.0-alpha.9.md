# Release record: 0.1.0-alpha.9

Record of what was published on scarbs.xyz as `0.1.0-alpha.9`, and how.

## The release commit

- Release commit: `32d0493d5c4037cae7285acd0bc28bfa84e30fe3`, on the branch `release/0.1.0-alpha.9` (kept, never
  merged), cut from `7c494f27fa5f3c703fdf20b46e840457cde17384`, the merge of the release pull request #260.
- Its whole diff removes the `[dev-dependencies]` of the six published crates. Their test helpers, `rapier_testing` and
  `rapier_golden`, are not published, so the manifests on `main` could not be packaged. `main` keeps the
  dev-dependencies (`slingfall/OPERATIONS.md` §7, the project manager's ruling with the Overseer of 2026-10-03).
- The release commit was landed by fast-forward (#262), never squash-merged, so the commit that was packaged is the
  commit on the branch.
- CI: every job that does not need the removed dev-dependencies is green on `32d0493`; the test jobs and
  `sink (rapier2d_classes)` are green on `7c494f2` on `main`.

## How it was published

- Five staged goes of the project manager: each crate verifies against its predecessors on the registry only after
  they are published, so a crate was packaged and published once the previous one was on the registry.
- Each archive was built by `RAYON_NUM_THREADS=1 scarb package -p <crate>` (no `--no-verify`, no `--allow-dirty`) from
  a clean clone detached at `32d0493` (its `VCS.json` names that commit), compared with `sha256sum -c`, published with
  `scarb publish -p <crate>` by the orchestrator, and read back from the registry after each.
- Tag `v0.1.0-alpha.9` on `32d0493`, and the GitHub release (pre-release):
  `https://github.com/bal7hazar/rapier-cairo/releases/tag/v0.1.0-alpha.9`.
