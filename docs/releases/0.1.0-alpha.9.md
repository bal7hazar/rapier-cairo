## How they were built

- Scarb 2.20.1 (Cairo 2.20.0), `RAYON_NUM_THREADS=1`.
- Machine: the VPS (Linux x86_64, 8 cores), one crate at a time through the shims (heavy lock).
- Path of the checkout: `/home/claude/.herdr/worktrees/rapier-cairo/hp-slingfall-rapier-t-0042-r9-release-0-1-0-alpha-9-prep`
  (the archive does not depend on it: `VCS.json` holds the commit and the path inside the repository).
- Plain `scarb package -p <pkg>` cannot run: `rapier_testing` and `rapier_golden` (dev-dependencies, not published) are
  not on the registry. As `scripts/release.sh` does, the `[dev-dependencies]` table was removed from the manifest of each
  of the six crates before packaging, then `scarb package -p <pkg> --no-verify --allow-dirty`, in the order below. The
  checkout was restored afterwards (`git checkout -- crates Scarb.lock`).
- `scripts/release.sh package` and `publish` build from a `git archive` copy, which has no git metadata: their
  archives carry no `VCS.json`, so their sha256 differ from the table. The table is for a build in a detached checkout.
- Reproducibility: `rapier_math` was packaged twice and gave the same sha256.
- To reproduce a row: clone, `git switch --detach 7c494f27fa5f3c703fdf20b46e840457cde17384`, drop the
  `[dev-dependencies]` tables of the six `crates/<pkg>/Scarb.toml`, run the commands above with `RAYON_NUM_THREADS=1`,
  `sha256sum target/package/*.tar.zst`.
