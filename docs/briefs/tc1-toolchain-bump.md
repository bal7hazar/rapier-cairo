# TC1 — toolchain bump: Scarb 2.20.1, starknet-foundry 0.64.0

Runner: `claude:opus` (measurements on every snapshot and probe). Lot id `tc1-toolchain-bump`, branch
`feat/tc1-toolchain-bump`.

## 1. Goal, context, files to read first

**Goal.** Move rapier-cairo from Scarb 2.19.4 / starknet-foundry 0.61.0 to **Scarb 2.20.1 / starknet-foundry 0.64.0**,
with every gas, steps and class-size figure re-measured and the results proved bit-identical.

**Context.** Owner's rule (2026-10-01, D-180, relayed by the project manager): every repository migrates to the latest
Scarb, and a compile drift's minimal case is run on the latest Scarb before any upstream issue. The project manager's
conditions for this lot: results bit-identical; a change of steps or of a class size is reported with before / after
tables, the slim caller's margin and every declared class against 73,728 first; **a numeric change stops the lot**. No
release comes with the bump. A toolchain bump is its own PR (`CLAUDE.md` § Boundaries): nothing else ships in it.

Read first: `AGENTS.md` (§3 the report, §6 validation, §7 the steps rule: "exact steps unchanged" needs before / after
tables on the P3, level **and** game-shaped probes), `CLAUDE.md` (stack, commands), `docs/BUDGETS.md` (how figures are
recorded), `scripts/gas.py` and `scripts/bytecode_size.py` (their docstrings), `.github/workflows/ci.yml`.

No optimisation. The targets are measurements, **before** (Scarb 2.19.4 / snforge 0.61.0 at `origin/main`, measured in

## 5. Tests

No test is added, removed or edited (§2). Bit-identity is shown by the existing tests passing unchanged on 2.20.1 /
0.64.0: the goldens (CI `golden` and the golden test crates), `crates/rapier2d/tests/game_path.cairo`,
`crates/rapier2d_classes/tests/{pile10,slim,removals,game_ticks}.cairo` (every `*_bit_identical` test), and the
full CI test groups. **A failing result test is a numeric change: stop, push what you have, report it under
Escalations with the failing tests and values. Do not adjust the test.**

**Compile drift.** If the new toolchain fails to compile, panics, or rejects code that 2.19.4 accepted: reduce it to a
minimal case, run that case on Scarb 2.20.1, and report it (code, command, output) under Escalations. Never open an
upstream issue yourself.
