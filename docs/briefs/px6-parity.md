`docs/API_PARITY.md` shows 89 in-scope items `missing`: dynamics 30, geometry 15, `parry::query` 20, `parry::shape` 24.

solver's scalar API; those wait for the study SC2).

Read first: `AGENTS.md` (the parity rule, the tests rule "tests live with their module"), `docs/API_PARITY.md`

## 3. Rules

- **Results:** bit-identical. A failing result test stops the lot: push what you have, stop, and report under
  Escalations. Never edit a test's expected value.
- **Steps:** report the P3 / level / game-shaped step probes before and after (exact, `--tracked-resource
  cairo-steps`); they must not move, since new API is off the step path.
- **Builds:** `RAYON_NUM_THREADS=1`; crate-scoped runs; whole-shot suites with `--max-threads 2`, one at a time; never
  `snforge test --workspace`. `scripts/prepush.sh` before each push (plain `git push`).
- **Programme rules:**
  - read CI logs only with `gh run view <run-id> --log-failed` alone in its call, after the run completes (never
    `gh api …/jobs/<id>/logs`);
  - your own git commands run normally, as separate commands;
  - signal only processes you started, by their recorded pid;
  - prefer words over links to external issues in PR text and commit messages;
  - push rarely: one push when done, then one per review's fixes.
