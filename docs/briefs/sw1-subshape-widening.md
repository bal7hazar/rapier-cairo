# SW1 — sub-shape result widening, as twin values

Runner: `impl-sonnet`, on the VPS (crate-scoped builds under the heavy lock; no whole-shot suite). Lot id
`sw1-subshape-widening`.

## 1. Goal and context

Port the 7 missing sub-shape items as opt-in API that changes no existing type, signature, result or step. Approved by
the project manager on 2026-10-03, in the layout that SC2 recommends.

The 7 items:
- `Contact::with_subshapes`;
- `PointProjection::with_subshape`;
- `RayIntersection::with_subshape`;
- `ContactManifold::{subshape_pos1, subshape_pos2, set_subshape_pos1, set_subshape_pos2}`.

Read first: `docs/research/parked-families.md` §2 (the design, the prototype and its measure), `AGENTS.md`,
`docs/adr/0001-upstream-divergences.md` (entries 35, 36, 45), `docs/API_PARITY.md` and `scripts/api_parity.py` (how
the matcher finds methods), the upstream sources (parry 0.31.1 at `/home/claude/git/refs/parry`, tag `v0.31.1`).

## 2. The design (SC2 §2.2, options 2A and 2B)

**2A — twin values**, beside the existing types:
- the types `SubshapeContact { contact, subshape1, subshape2 }`, `SubshapePointProjection { projection, subshape }`
  and `SubshapeRayIntersection { intersection, subshape }`;
- the builders `with_subshapes` / `with_subshape`, **placed in the existing traits** `ContactTrait`,
  `PointProjectionTrait` and `RayIntersectionTrait`, so that the parity matcher finds them by name.

**2B — computed poses:**
- `subshape_pos1 / 2(self: @ContactManifold, shape1: @Shape) -> Option<Pose2>` read the part pose back from the
  shape, as the narrow phase does (ADR 36);
- `set_subshape_pos1 / 2` follow SC2's recommendation: on `SubshapePoses`, or closed with a reason. Say which, and
  record the deviation (one more argument than upstream) as a new ADR entry.
